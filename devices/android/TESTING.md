# Сценарий ручной проверки фермы и демона

Всё запускается из `sdk/` (`cargo build`). APK сервера: `devices/android/app-screencast/server-adb/build/outputs/apk/debug/server-adb-debug.apk`
(`export PCDOCK_SERVER_APK=...` или ключ `--server-apk`). Два телефона проброшены в WSL (`usbipd attach --wsl --auto-attach`).
Не переключайте режим USB на телефоне командами `svc usb`: `usbipd` не подхватит новый USB-ID.

Серийники: `adb devices` (ADB) и `./target/debug/pcdock-probe --list --serials` (USB).

## 1. Обнаружение (демон только смотрит)
| # | Команда | Ожидается |
|---|---|---|
| 1.1 | `pcdockd --auto --no-usb --server-apk $APK` | оба телефона по ADB: в логе трубки, состояние `ready` у обоих |
| 1.2 | то же, выдернуть кабель одного телефона на 5 с | `lost` только после 45 с; при возврате прежний номер |
| 1.3 | `pcdockd --auto --no-adb` (только Redmi в USB-режиме, приложение запущено) | `ready`, видео идёт |
| 1.4 | `pcdockd --auto` на телефоне без приложения (Oppo до установки) | сначала `needs_app`, через ~20 с переход на ADB и `ready` |
| 1.5 | в 1.4 добавить `--no-fallback` | остаётся `needs_app` (без перехода) |
| 1.6 | `pcdockd --auto --prefer <серийник Redmi>=adb` | Redmi идёт по ADB, а не по USB |
| 1.7 | `pcdockd --phone adb:<серийник>` (без `--auto`) | только этот телефон |
| 1.8 | `pcdockd --auto --except <серийник Oppo>` | Oppo пропущен |
| 1.9 | `pcdockd` без аргументов | ошибка «нужен --auto или --phone», код 2 |
| 1.10 | `pcdockd --auto --vid 0x2a70` | запускается; чужие USB-устройства не трогаются |

## 2. Подготовка телефона (состояния с подсказками)
| # | Что сделать | Ожидается |
|---|---|---|
| 2.1 | отозвать отладку («Отозвать разрешения отладки по USB»), переподключить, `pcdockd --auto --no-usb` | `needs_auth` с подсказкой; после «Разрешить» → `ready` без перезапуска |
| 2.2 | остановить запись экрана в уведомлении приложения (AOA-режим) | `needs_permission`; после «Начать» → `ready` |

## 3. Слушатели демона
| # | Команда | Ожидается |
|---|---|---|
| 3.1 | `pcdockd --auto --tcp 127.0.0.1:9001 --ws 127.0.0.1:9002 --local pcdock` | три слушателя в логе |
| 3.2 | `pcdockd --auto --tcp 0.0.0.0:9001` | отказ: не на localhost нужен пароль, код 2 |
| 3.3 | то же с `--token abc` | слушает; клиент без `Auth` получает «нужна авторизация», с верным токеном — работает |
| 3.4 | `PCDOCK_TOKEN=abc pcdockd --auto ...` | то же, что `--token` |

## 4. Ввод и видео (через демо-программы или `pcdock-probe`)
| # | Проверка | Ожидается |
|---|---|---|
| 4.1 | свайп сверху вниз на обоих телефонах (ADB и AOA) | открывается шторка |
| 4.2 | Esc | закрывает шторку |
| 4.3 | повернуть телефон | размер потока меняется, касания попадают в нужное место |
| 4.4 | мышь и касание одновременно | режимы взаимоисключающие (в демо), клавиатура независима |
| 4.5 | включить звук на телефоне (видео, музыка) | в потоке звука пик не нулевой (AOA и ADB) |
| 4.6 | погасить экран, `Wake` | экран включается, видео возобновляется |
| 4.7 | `Watch`/`Unwatch` | видео идёт только от тех телефонов, за кем следят |

## 5. Переключение режима (после реализации `set_transport`)
Телефон на ADB → переключить на USB (нужно приложение) → обратно. Номер не меняется, ввод и видео продолжаются.
