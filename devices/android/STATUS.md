# Статус — PC Dock / Android

Обновлено: 2026-10-28. Проверено на: Redmi A5 (`25028RN03A`), Android 15, HyperOS (V140), ПК — WSL2.

## Работает (проверено)

- Видеопоток экрана телефона в окно на ПК по USB (AOA), кадры 360×820.
- Автозапуск приложения системой при подключении (по `USB_ACCESSORY_ATTACHED`), включая запуск из состояния «остановлено».
- Сервис держит захват экрана независимо от кабеля: после отключения и подключения кабеля поток возвращается без новых диалогов.
- Диалог записи экрана подтверждается один раз после запуска приложения.
- Проекция переживает блокировку экрана (подтверждено вручную).
- Уведомление «Док-станция» с кнопкой «Остановить» (проверено вручную).
- Telegram, Instagram, Chrome показываются нормально.
- Ввод доходит до телефона: тачскрин, клавиатура и мышь регистрируются как HID, события видны в `getevent`; отключение устройств по `F10/F11/F12` и флагам `--no-*`.
- Сброс USB после 6 с тишины, если телефон уже был в режиме аксессуара и приложение не запущено.
- Уборка при выходе: снятие HID и сброс USB возвращает телефон в обычный режим (проверено на SIGTERM, ~3 с).

## Приложение на протоколе v2 (проверено 2026-10-28)

Приложение (`Protocol.kt`, `Link.kt`, `ScreenCaptureService.kt`) говорит по протоколу v2. **Проверено вживую** ядром SDK (`pcdock-probe`) на вашем телефоне:
- Обмен `HELLO` в обе стороны, согласование версии 2, `DisplayInfo`, кадры JPEG с метками времени; `PING`/`PONG` держат сессию без таймаутов.
- **Поворот экрана:** на каждый поворот (0°, 90°, 180°, 270°) приходит новый `DisplayInfo`, размер потока меняется (360×820 ↔ 820×360), и **сами JPEG-кадры** действительно меняют размер (проверено по заголовку JPEG).
- **`SET_STREAM`:** по запросу поток переключился на 720×1640, `DisplayInfo` с итоговым размером пришёл.
- **Запасной режим v1:** старый Python-`viewer` без `HELLO` через ~2.5 с начал получать кадры (проверено).
- Запись в USB вынесена в отдельный поток: в очереди остаётся только последний кадр.

Не проверено: ограничение частоты кадров (`max_fps`) и качество JPEG на живом экране (на статичном экране кадров нет), поведение при очень долгом молчании ПК. Мелочь: после `SET_STREAM` `DisplayInfo` приходит дважды (безвредно).

Новое с 2026-10-28 (реализовано, ждёт живой проверки): звук (`AudioPlaybackCapture` + mute, PCM), побудка (`WAKE`, экран на минуту), горизонтальный скролл (AC Pan, 7-й байт отчёта), viewer на SDK (`pcdock-ffi`, Питон-протокола нет).

## SDK (ядро на Rust)

`sdk/pcdock-core`: пакеты, HID-отчёты, ввод, сессия; 50 тестов. `sdk/pcdock-usb`: USB-адаптер (поиск телефона, handshake, переподключение, сброс при молчании, чистый выход), 3 теста. `sdk/pcdock-ffi`: C ABI поверх ядра, 3 теста. **Проверено на вашем телефоне** утилитой `pcdock-probe`: регистрация трёх устройств, тап с точными координатами, силой и площадью, сброс USB при молчании, переподключение, возврат телефона в обычный режим при выходе. `viewer` переведён на SDK (говорит на v2 через `pcdock-ffi`, Питон-протокола больше нет). Подробности в `sdk/README.md`.

## Исправлено 2026-10-27: «тачскрин» вёл себя как тачпад

Виртуальный тачскрин (однопальцевый дескриптор Digitizer) не получал от ядра признак «прямое касание» (`INPUT_PROP_DIRECT`), и Android вёл его в режиме тачпада (`Touch Input Mapper (mode - POINTER)`, на экране появлялась стрелка курсора). Теперь это многоточечный экран в стиле Windows 8 (драйвер `hid-multitouch`): режим `DIRECT`, 10 пальцев, площадь и сила касания. Проверено на телефоне: два пальца (слоты 0 и 1), оверлей системы показывает отправленные `Prs: 0.70` и `Size: 0.04`, касание ложится в нужную точку. См. `DECISIONS.md`, решение 12.

## Проверено 2026-10-28: поворот экрана и тачскрин

Android поворачивает координаты виртуального тачскрина вместе с экраном (он привязан к корпусу). Измерено в Chrome на всех четырёх поворотах (пять точек); обратное преобразование в ядре (`pcdock-core::hid::to_device_coords`) совпадает со всеми измерениями. Сам **захват экрана** при повороте приложение пока не поддерживает (кадры остаются фиксированного размера), это следующий шаг.

## Не проверено (живой чек-лист)

- **Ввод руками в окне**: реальные клики, свайпы, колесо и клавиши. Проверялось только синтетическими событиями.
- Точность совпадения курсора мыши на телефоне с положением в окне (ускорение указателя Android).
- Поведение **мыши** при повороте экрана (тачскрин проверен, см. `DECISIONS.md`, решение 13).
- **Звук вживую**: `[sdk] Audio: codec=1` в логе viewer, тишина динамика телефона, слышно на ПК. Нужен новый APK.
- **Побудка**: `F8` при погасшем экране → экран на минуту, ввод PIN. Нужен новый APK.
- **Горизонтальный скролл**: наклон колеса в широкой ленте. Если Android игнорирует AC Pan — менять кодировку.
- Работа сервиса в фоне в течение суток (убьёт ли HyperOS сервис).
- Поведение при реальном выдёргивании кабеля (проверялось имитацией через `adb reconnect`).

## Известные проблемы

- **Зависание картинки (лечится само или в один тап).** Если сессия встала (PONGи идут, кадров нет),
  viewer раз в 2 с шлёт `REQUEST_FRAME`, а телефон снимает «паузу по тишине» по любому пакету от ПК
  (раньше ждал только `HELLO` — сессия умирала навсегда). Если встала сама проекция (система её
  остановила), сервис больше не умирает: в уведомлении появляется «Разрешить снова», тап ведёт
  на диалог записи экрана, захват перезапускается в живом сервисе. В hb-логе видно
  `проекция=жива/МЕРТВА` и `кадр_назад=Nс`.
- **Выдёргивание кабеля вешало viewer.** `get_string` без таймаута и `dev.reset()` на полумёртвом
  usbip (WSL2) могли встать насмерть. Теперь: всем перечисленным устройствам ставится таймаут,
  `reset` идёт в демоне-потоке с таймаутом 5 с, выдернутый кабель детектится сразу
  (`NO_DEVICE` → быстрое переподключение без traceback).
- **После переустановки (`dev.sh`) диалог записи экрана спросится заново — это нормально.**
  Токен проекции одноразовый и умирает вместе с процессом; `dev.sh` после установки сам открывает
  приложение, подтвердите диалог один раз. Обычное переподключение кабеля диалога не требует.

- **Сброс USB сразу после перехода в режим аксессуара рвёт проброс `usbipd`**: телефон исчезает из WSL и возвращается автоаттачем только через ~24 с (в журнале ядра `vhci_hcd: connection closed`, потом `Device attached`). В обычных случаях сброс проходит за ~3 с без разрыва. Воспроизводилось один раз в тесте «выход сразу после handshake»; в обычной работе такого быть не должно.

- Один раз приложение не запустилось само при подключении; причина не установлена. Вероятно, телефон уже был в режиме аксессуара (см. `DECISIONS.md`, решение 7), но не подтверждено.
- Запись в USB блокируется, пока ПК не читает (наблюдалось 109 с). Сервис при этом не отвечает на опрос USB и не пишет heartbeat.
- Окна с `FLAG_SECURE` будут чёрными (ограничение `MediaProjection`).
- Размер кадра зашит; поворот захвата на телефоне не поддержан (координаты ввода поворот уже учитывают).
- После убийства `main.py` на телефоне остаются зарегистрированные HID-устройства до следующего коннекта (новый коннект их перетирает и чистит).
- Отладочные логи включены везде, на ПК и на телефоне (шумно).
- Проект не под git, тестов нет.
- Названия «Device Media» / `com.device.media` унаследованы от форка.
