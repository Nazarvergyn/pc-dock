# PC Dock — Android

Телефон подключается к ПК одним кабелем и превращается в «док-станцию»: его экран показывается в окне
на ПК, а мышь, клавиатура и тачскрин ПК управляют телефоном. **Режим разработчика и отладка по USB
на телефоне не нужны.**

## Из чего состоит

| Часть | Где | Что делает |
|---|---|---|
| Приложение «Device Media» (Kotlin) | `app-screencast/` | Захватывает экран, сжимает в JPEG и отправляет по USB |
| Приложение для ADB-режима (сервер) | `app-screencast/server-adb/` | Серверный процесс с правами shell: экран, ввод, звук без диалога записи; запускается с ПК |
| Демоны на ПК (Rust) | `../../sdk/` | `pcdockd` (ферма телефонов) и `pcdock-autod` (автоматизация): всё, что делает ПК-сторона |
| Скрипт разработки | `dev.sh` | Собрать, поставить на телефон, запустить, снять логи |

## Как это работает

### 1. USB Accessory (AOA)
ПК подключён к телефону как **USB-хост**, а телефон работает как **аксессуар** по протоколу
Android Open Accessory. Отладка (adb) для этого не нужна: это обычный штатный режим Android.

1. Телефон подключается в обычном режиме (зарядка / MTP).
2. Демон на ПК находит его по USB (список VID в `ANDROID_VIDS`) и шлёт AOA handshake: проверка версии
   протокола (нужна **2** — из-за HID), шесть строк (производитель, модель, описание, версия, URI, серийник)
   и команду START.
3. Телефон пересоздаёт USB как `18d1:2d00/2d01` (режим аксессуара; `2d01` = accessory + ADB, если отладка
   включена) и **сам запускает приложение**, у которого в манифесте есть фильтр на такую пару
   `manufacturer/model/version` (`app/src/main/res/xml/accessory_filter.xml`).

> Строки `PCDock` / `DeviceMedia` / `1.0` в настройке фермы (`PCDock` / `DeviceMedia` / `1.0` по умолчанию) и в `accessory_filter.xml` **должны совпадать**,
> иначе система не найдёт приложение для аксессуара.

Интерфейс 0 в режиме аксессуара — bulk-канал для данных (IN `0x81` — кадры с телефона).
Интерфейс 1 — adb (если включён); демон его не трогает.

### 2. Поток видео
Приложение (`ScreenCaptureService`) создаёт `VirtualDisplay` через `MediaProjection`. Кадры приходят в
`ImageReader` в формате `RGBA_8888` (JPEG там напрямую не поддерживается), превращаются в `Bitmap` и
сжимаются в JPEG (качество 70). Размер захвата — **половина** экрана телефона (чётные ширина и высота).

Формат кадра в USB:

```
[4 байта: длина JPEG, big-endian][JPEG...][4 байта длины][JPEG...] ...
```

На ПК `extract_jpeg` режет поток на кадры, а при мусоре ищет маркер `FFD8` и перестраивается.
Декодируется только **последний** кадр из прочитанных (иначе копится задержка).

### 3. Сервис живёт отдельно от кабеля
Главная идея: **диалог «Начать трансляцию экрана» нужен один раз**, а не при каждом подключении.

- `MainActivity` только просит разрешение на запись экрана и запускает сервис, потом закрывается.
  Если сервис уже работает, она закрывается сразу.
- `ScreenCaptureService` — foreground-сервис с уведомлением «Док-станция» (кнопка **Остановить**).
  Он держит `MediaProjection`/`VirtualDisplay` постоянно и сам:
  - раз в секунду ищет USB-аксессуар и подключается к нему;
  - при обрыве кабеля (`IOException`, `ACCESSORY_DETACHED`) закрывает поток и ждёт следующего подключения;
  - запоминает последний кадр и **сразу отправляет его при подключении** (экран может не меняться);
  - без USB не тратит CPU: JPEG делается не чаще раза в секунду.
  - пока USB подключён, экран можно разбудить кнопкой «Будить» (`F8`, пакет `WAKE`):
    включается на минуту — видно PIN-пад, код вводится тачем/клавиатурой. Постоянно экран
    не держим, чтобы не сажать батарею.
  - по `SET_STREAM(audio=1)` захватывает звук приложений (`AudioPlaybackCapture`, Android 10+)
    и глушит свой динамик (как колонка); громкость возвращает при выключении звука или обрыве.
- USB-разрешение выдаётся автоматически, когда активность запущена системой по `USB_ACCESSORY_ATTACHED`.
  Если сервис запрашивает его сам (`requestPermission`), покажется диалог.

### 4. Ввод (AOA HID)
Через AOA 2 ПК регистрирует на телефоне **виртуальные HID-устройства** (запросы 54–57, обычные control
transfer на уже открытое устройство; приложение для ввода не нужно):

| Устройство | HID id | Что делает |
|---|---|---|
| Тачскрин (мультитач) | 1 | До 10 пальцев: `tip`, `contact_id`, X, Y (0..32767), площадь, сила. Режим `DIRECT` (дескриптор в стиле Windows 8). Левая кнопка и перетаскивание = тап и свайп |
| Клавиатура | 2 | Стандартный отчёт 8 байт; код клавиши = SDL scancode = USB HID usage |
| Мышь | 3 | Относительное движение (16 бит), 3 кнопки, колесо. Правая кнопка = «Назад» |

Курсор мыши: телефон не сообщает, где курсор, поэтому его положение **оценивается ядром SDK**: при первом движении он
«прижимается» к углу (−32767), потом уходит в нужную точку. Размер экрана телефон присылает в `DisplayInfo`,
координаты ввода — доли картинки.

Устройства можно отключать по отдельности (регистрация на телефоне отменяется, «призрачного» курсора нет):
горячие клавиши в окне `F10` (касание), `F11` (мышь), `F12` (клавиатура) или флаги запуска
`--no-touch`, `--no-mouse`, `--no-keyboard`. Эти клавиши на телефон не отправляются.

HID **не переживает переподключение** — демон регистрирует устройства заново после каждого подключения.

### 5. Жизненный цикл

```
 кабель вставлен ─► обычный режим ─► [ПК: handshake] ─► режим аксессуара
                                                              │
                          система запускает MainActivity ◄────┘ (USB_ACCESSORY_ATTACHED)
                                    │
              сервис уже работает? ─┤
                 да: закрыться      │ нет: диалог записи экрана (1 тап) ─► старт сервиса
                                    ▼
                   сервис подключается к аксессуару, шлёт кадры ─► ПК рисует окно, шлёт ввод
```

Кабель выдернули/вставили: сервис остаётся, ПК делает handshake заново, диалогов нет.

**Важная особенность.** Приложение запускается системой **только в момент перехода в режим аксессуара.**
Если телефон уже в нём (скрипт перезапустили при живом соединении, остался после аварии), событий нет и
приложение не стартует. Поэтому если от телефона 6 секунд нет данных, демон сбрасывает USB, телефон
переподключается, и приложение запускается (не чаще раза в 60 с, максимум 3 попытки подряд).

## Запуск

Требования: Linux/WSL2, Rust и libusb, JDK 17 и Android SDK (для сборки), на телефоне Android 8+ (проверено на Android 15, HyperOS).

```bash
# Один раз: собрать и поставить приложение (нужна отладка по USB только на время установки)
./dev.sh install

# Каждый день
../../sdk/target/release/pcdockd --auto --server-apk server-adb/build/outputs/apk/debug/server-adb-debug.apk
```

`dev.sh`: `./dev.sh` — полный цикл (сборка, установка, запуск, логи), `./dev.sh install`, `./dev.sh logs`.
Логи пишутся в `logs/` (`pc.log`, `phone.log`).

**WSL2:** USB надо пробрасывать через `usbipd-win`. Телефон меняет VID:PID при переходе в режим аксессуара,
поэтому нужен `usbipd attach --wsl --auto-attach` на оба режима (по `--hardware-id`).

**Первый запуск на телефоне:** разрешить уведомления; на HyperOS/MIUI — автозапуск и «Всплывающие окна в фоне»
для приложения, отключить оптимизацию батареи.

## Отладка

- Логи телефона: `adb logcat -s DeviceMedia AndroidRuntime`. Сервис пишет heartbeat раз в 5 с
  (`[hb ...]`: подключение, число кадров, байт, время записи).
- Логи ПК: временные метки, дамп USB-устройств и дескрипторов, `[stat]` раз в 2 с.
- В режиме аксессуара adb работает, только если отладка включена (`2d01`). Если `adb push` зависает,
  выполните `adb reconnect`, чтобы телефон вернулся в обычный режим.

## Известные ограничения и подводные камни

- **`FLAG_SECURE`.** Окна, защищённые от записи (банки, часть экранов мессенджеров), показываются чёрными.
  Это ограничение `MediaProjection`.
- **Диалог записи экрана** нужен после перезагрузки телефона и после остановки трансляции.
- **Запись в USB без читателя блокируется** (наблюдалось 109 с), пока ПК не вернётся к чтению.
- **Один палец.** Многоточечных жестов нет.
- **Курсор мыши** может расходиться с положением из-за ускорения указателя Android.
- Размер кадра зашит; поворот захвата на телефоне не поддержан.
- **Приложение при убитом `main.py`** оставляет HID-устройства на телефоне до следующей регистрации.
- Названия «Device Media» / `com.device.media` унаследованы от форка.

## Что пришлось учесть (грабли)

- Android 14+: `PendingIntent` для `requestPermission` с `FLAG_MUTABLE` и неявным интентом требует
  `FLAG_ALLOW_UNSAFE_IMPLICIT_INTENT`; иначе приложение падает.
- `Activity.RESULT_OK == -1`: нельзя использовать `-1` как «нет данных».
- Android 14+: до `createVirtualDisplay` обязателен `MediaProjection.registerCallback`, а `startForeground`
  должен быть с типом `mediaProjection`.
- `ImageReader` у `VirtualDisplay` — только `RGBA_8888`.
- `UsbAccessory.getSerial()` без разрешения бросает `SecurityException`.
