# PC Dock: документация

Продукт: **демоны** для управления Android-телефонами. `pcdockd` держит ферму телефонов (экран, звук, ввод, файлы), `pcdock-autod`
запускает сценарии на Lua как автотесты. Единственный интерфейс продукта это их протокол ([protocol.md](protocol.md)); как библиотека продукт
не поставляется.

Телефонов может быть много; пути подключения: USB-аксессуар (AOA), ADB, последовательная труба. Подключение, отключение,
выбор пути и подготовка телефона обрабатываются автоматически.

## Проверка на вашей машине

`pcdock-check` находит телефоны, проверяет окружение (USB, ADB), готовность, размер экрана, поток кадров и, по флагу `--input`, ввод. Один исполняемый файл
для Linux, macOS и Windows; отчёт в консоль и в JSON (`--json`).

## Что проверено, а что нет

Проверено на реальных телефонах (Redmi A5 и Oppo CPH2505, Android 15, Linux в WSL2): ADB-режим (запуск сервера, видео, касание, клавиша,
поворот, звук как канал), AOA-режим на Redmi, потеря и возврат телефона, состояния `needs_app` и `needs_access`, два телефона, hotplug. Демоны
`pcdockd` и `pcdock-autod` проверены тестами на фейковых телефонах (около 170) и запуском бинарников с реальным клиентом. CI (GitHub Actions) собирает и тестирует всё на Linux, Windows, macOS и Android (зелёный); на настоящей Windows запускались `pcdock-check.exe`, `pcdockd.exe` и
`pcdock-autod.exe` (libusb, именованная труба), телефона на Windows не было. Не проверено на железе: передача файлов и сценарии автоматизации на настоящем телефоне,
запуск на настоящем macOS. Подробно: «Известные ограничения» в [operations.md](operations.md).
