# Пути подключения

## Сравнение

| | AOA (`usb`) | ADB (`adb`) | Serial (`serial`) |
|---|---|---|---|
| Режим разработчика и отладка по USB на телефоне | не нужны | нужны | не нужны |
| Приложение на телефоне | нужно (PC Dock) | не нужно | зависит от прошивки |
| Диалог записи экрана | один раз после перезапуска приложения | нет | зависит от прошивки |
| Ввод | HID-устройства USB (как настоящие) | события ввода от процесса shell | как AOA/ADB, через пакеты |
| Что ломается при смене режима USB | телефон меняет USB-ID (`2d00`/`2d01`) | — | — |
| Проверено | да (Redmi) | да (Redmi, Oppo) | только на паре сокетов |

Общее для всех путей: один и тот же протокол v2 поверх байтового канала ([`PROTOCOL.md`](../../devices/android/PROTOCOL.md)).

## AOA: USB-аксессуар

**Как работает.** ПК выполняет AOA-рукопожатие (управляющие запросы USB): передаёт телефону строки (производитель `PCDock`, модель
`DeviceMedia`, версия `1.0`), телефон переключается в режим аксессуара (`18d1:2d00` или `2d01`) и система запускает приложение с
подходящим фильтром. Приложение захватывает экран (MediaProjection) и шлёт кадры по USB bulk; ввод ПК регистрирует как HID-
устройства (тачскрин с несколькими пальцами и силой, мышь, клавиатура).

**Что нужно.**
1. На телефоне установлено приложение PC Dock; строки в нём и в настройке фермы совпадают (по умолчанию совпадают).
2. При первом подключении Android спросит, открывать ли приложение для этого аксессуара: подтвердить.
3. Один раз после запуска приложения разрешить запись экрана. Заново нужно после перезагрузки телефона, перезапуска
   приложения или остановки в уведомлении.
4. На ПК доступ к USB-устройству (см. «Подготовка ПК» ниже).

**Особенности.**
- Приложение запускается системой **только в момент перехода** в режим аксессуара. Поэтому, если телефон молчит, ферма сбрасывает
  USB (не чаще раза в минуту, не больше 3 попыток подряд) и повторяет рукопожатие.
- При выходе ферма возвращает телефон в обычный режим (сброс USB). Если процесс убит жёстко, телефон может остаться в режиме
  аксессуара, и при следующем запуске приложение само не стартует; помогает переподключение кабеля.
- Телефон меняет USB-ID при переходе, а адрес порта может смениться (в WSL это бывает всегда), поэтому телефон надёжнее
  закреплять по серийнику, чем по порту.

## ADB: серверный процесс с правами shell

**Как работает.** Ферма говорит с сервером ADB на ПК (`127.0.0.1:5037`), кладёт на телефон файл сервера (`/data/local/tmp/pcdock-server.apk`),
запускает его командой `app_process` от пользователя shell, пробрасывает его abstract-сокет на локальный порт ПК и по нему
ведёт тот же протокол. Серверу не нужно приложение и диалог записи экрана: экран берётся зеркальным виртуальным дисплеем, ввод
подаётся системной службой ввода, звук собирается через `AudioRecord` источником REMOTE_SUBMIX.

**Что нужно.**
1. На телефоне включена отладка по USB; компьютер подтверждён («Разрешить отладку», лучше «Всегда»).
2. На ПК установлен `adb` и доступен сервер ADB (ферма его не запускает: `adb start-server`).
3. APK сервера: `server-adb-debug.apk` (сборка: `./gradlew :server-adb:assembleDebug` в `devices/android/app-screencast`). Путь
   задаётся ключом `server_apk`, параметром `--server-apk` или переменной `PCDOCK_SERVER_APK`.

**Особенности.**
- Сервер живёт, пока ферма держит открытым его поток; закрытие фермы завершает сервер.
- Сокет сервера доступен всем приложениям телефона, поэтому сервер принимает соединение только от пользователя shell (adbd), чужие
  закрывает.
- Версии: проверено на Android 15 (SDK 35). Для других версий используются закрытые системные интерфейсы (захват экрана,
  ввод, звук); они менялись между версиями, поэтому ниже Android 13 работу не гарантируем.
- Ввод приходит как от виртуального устройства, а не от настоящего HID (для AOA наоборот).
- ADB не показывает телефон в режиме «только зарядка» без отладки и в режиме аксессуара без ADB.

## Serial: труба микроконтроллера

По последовательному порту идут те же байты протокола; управляющие запросы HID кодируются пакетом `0xC0`. Прошивка протокол не
знает, только пересылает байты. Скорость `serial_baud` (у USB-CDC не влияет). Источник ищет `ttyACM*`, `ttyUSB*` (Linux),
`cu.usbmodem*`, `cu.usbserial*` (macOS), COM-порты (Windows). Включается явно (`serial: true`, `--serial`), потому что порты
открываются и получают байты протокола, а на них могут сидеть чужие устройства. Проверено только на паре сокетов.

## Подготовка ПК

### Linux

- Установить `libusb-1.0` (для сборки: пакет с заголовками, `libusb-1.0-0-dev`).
- **Права на USB-устройства.** Файлы устройств в `/dev/bus/usb` по умолчанию доступны только root. Нужны правила udev, которые
  выдают права вашей группе. Готовые правила для списка производителей: `pcdock-probe --udev-rules | sudo tee
  /etc/udev/rules.d/51-pcdock.rules`, затем `sudo udevadm control --reload && sudo udevadm trigger --action=add --subsystem-match=usb`
  и переподключить телефон. Пакет `adb` (`android-sdk-platform-tools-common`) уже содержит правила `51-android.rules` для
  группы `plugdev`: достаточно, чтобы udev работал и пользователь состоял в группе.
- Без прав ферма сообщает `needs_access`.

### WSL2

USB в WSL2 не виден сам: его передаёт Windows программой `usbipd-win` (на Windows: `usbipd bind --busid <id>` от администратора, затем
`usbipd attach --wsl --auto-attach --busid <id>`). Особенности, о которые легко споткнуться:
- **Для режима аксессуара нужно разрешить и его USB-ID** (`usbipd bind --hardware-id 18d1:2d00` и `18d1:2d01`): телефон меняет ID при
  переходе, и без разрешения он пропадает из WSL.
- Некоторые телефоны (например, Oppo) меняют USB-ID и при смене режима USB. Новый ID тоже надо разрешить.
- После сброса USB телефон возвращается в WSL до ~40 с (поэтому `lost_after` по умолчанию 45 с).
- В WSL должен работать **udev** (иначе права на устройства не выдаются): включите systemd в `/etc/wsl.conf` (`[boot]` `systemd=true`),
  перезапустите WSL (`wsl --shutdown`) и проверьте `ps -p 1 -o comm=` (должно быть `systemd`).
- Для ADB-режима проброс USB не нужен, если использовать `adb` Windows и `adb_server` (требует настройки сети/файрвола).

### Windows

Для AOA нужен драйвер WinUSB на устройстве телефона (в обычном режиме и в режиме аксессуара `2d00`/`2d01`), например через Zadig.
Без драйвера ферма сообщает `needs_access`. Для ADB нужен `adb.exe` и драйвер производителя. Не проверялось.

### macOS

Обычно доп. драйверы не нужны; `brew install libusb`. На macOS открытие телефона через libusb может мешать `adb`; серийник читается
только один раз на порт. Выбор по портам проверен частично (чтение списка с двумя телефонами). Не проверялось полностью.
