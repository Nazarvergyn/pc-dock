# Руководство по эксплуатации

Для тех, кто устанавливает, запускает и сопровождает демоны: `pcdockd` (ферма телефонов) и `pcdock-autod` (автоматизация).

## 1. Требования

| Что | Требование |
|---|---|
| ОС ПК | Linux (проверено, в том числе в WSL2). macOS: частично. Windows: не проверялась |
| Сборка | Rust 1.82+ (проверено на 1.99), `libusb-1.0` с заголовками (Linux: `libusb-1.0-0-dev`; macOS: `brew install libusb`) |
| ADB-режим | `adb` (платформа-тулс) на ПК, APK сервера |
| AOA-режим | приложение PC Dock на телефоне |
| Телефон | Android; ADB-режим проверен на Android 15, AOA на Android 15; закрытые интерфейсы для ADB-сервера менялись между версиями |
| Производитель USB | один из списка `ANDROID_VIDS` (Google, Samsung, HTC, Huawei, Honor, Xiaomi, Motorola, OnePlus, Oppo/Realme, Vivo, Nothing, HMD, Sony Ericsson, LG, ZTE) или добавленный через `--vid` |

## 2. Установка

```bash
cd sdk
cargo build --release                         # sdk/target/release/: pcdockd, pcdock-autod, pcdock-check, pcdock-probe
cd ../devices/android/app-screencast
./gradlew :server-adb:assembleDebug            # APK сервера для ADB-режима
./gradlew :app:assembleDebug                   # приложение для AOA-режима (если нужен AOA)
```

Выходные файлы:
- `sdk/target/release/pcdockd` демон фермы; `pcdock-autod` демон автоматизации; `pcdock-check` самопроверка; `pcdock-probe` диагностика USB.
- Готовые архивы для Linux, Windows и macOS, подписанные APK и `SHA256SUMS` собирает релиз (см. `development.md`).
- `devices/android/app-screencast/server-adb/build/outputs/apk/debug/server-adb-debug.apk` сервер ADB-режима.
- `devices/android/app-screencast/app/build/outputs/apk/debug/app-debug.apk` приложение AOA-режима.

Приложение AOA ставится на телефон обычным способом (например, `adb install -r app-debug.apk`; на Xiaomi/Oppo на экране телефона
придётся подтвердить установку по USB). Сервер ADB-режима ставить не нужно: ферма сама кладёт его на телефон.

## 3. Подготовка ПК

См. [transports.md](transports.md#подготовка-пк): права на USB (udev), WSL2 (usbipd, systemd), Windows (WinUSB), macOS.
Проверка на Linux:

```bash
lsusb | grep -i -E "18d1|2717|22d9|04e8"      # телефон виден
ls -l /dev/bus/usb/001/                        # у файла телефона группа plugdev, права rw для группы
adb devices                                    # телефон в списке (для ADB-режима)
./target/release/pcdock-probe --list --serials # телефон виден фермой, серийник читается
```

Если в `pcdock-probe --list --serials` серийник `-`, у процесса нет доступа к устройству.

## 4. Подготовка телефона

**ADB-режим:** включить «Для разработчиков» → «Отладка по USB»; при подключении нажать «Разрешить» (отметить «Всегда
разрешать»). На Xiaomi/HyperOS дополнительно может потребоваться «Отладка по USB (настройки безопасности)»: на проверенном Redmi A5 не
понадобилась.

**AOA-режим:** установить приложение; при первом подключении подтвердить запуск для аксессуара; разрешить запись экрана. На
Xiaomi/HyperOS включить автозапуск и «Всплывающие окна в фоне» для приложения, иначе система может не запускать его при подключении.

## 5. Запуск

Демон на всех найденных телефонах:

```bash
./target/release/pcdockd --auto --server-apk /opt/pcdock/server-adb-debug.apk
```

Проверка: в логе должны появиться слушатели (`TCP: 127.0.0.1:9001`, `WS: …`, `local: pcdock`) и строка `автообнаружение включено`; при появлении
телефона демон шлёт клиентам событие `Appeared`, затем `State` (`ready`).

Типовые варианты:

| Задача | Команда |
|---|---|
| только ADB, без USB | `pcdockd --auto --no-usb --server-apk APK` |
| только USB (AOA), без ADB | `pcdockd --auto --no-adb` |
| только перечисленные телефоны | `pcdockd --phone adb:СЕРИЙНИК1 --phone usb:СЕРИЙНИК2 --server-apk APK` |
| всё, кроме одного | `pcdockd --auto --except СЕРИЙНИК --server-apk APK` |
| этот телефон всегда по ADB | `pcdockd --auto --prefer СЕРИЙНИК=adb --server-apk APK` |
| не переходить на другой путь при неудаче | `pcdockd --auto --no-fallback ...` |
| со звуком | `pcdockd --auto --audio ...` |
| для доступа с другого компьютера | `pcdockd --auto --tcp 0.0.0.0:9001 --token СЕКРЕТ ...` (+ защищённый туннель) |
| неизвестный производитель USB | `pcdockd --auto --vid 0x2a70` |

Коды завершения: `0` штатно; `2` ошибка настройки (нет `--auto` и `--phone`, неверный формат, слушатель не на localhost без пароля).

Автоматизация поверх фермы (сценарии на Lua как автотесты, см. [autod.md](autod.md)):

```bash
./target/release/pcdock-autod --farm 127.0.0.1:9001 --data /var/lib/pcdock-autod
```

Передача файлов на телефоны и с них включается у фермы: `pcdockd --files` (по ADB, папки `/sdcard`, `/storage/emulated/0`, `/data/local/tmp`; свои: `--files-root`).

### Автозапуск (systemd)

```ini
# ~/.config/systemd/user/pcdockd.service
[Unit]
Description=PC Dock daemon

[Service]
Environment=PCDOCK_SERVER_APK=/opt/pcdock/server-adb-debug.apk
Environment=RUST_LOG=info
ExecStart=/opt/pcdock/pcdockd --auto
Restart=on-failure

[Install]
WantedBy=default.target
```

Для `pcdock-autod` аналогичная служба с `ExecStart=/opt/pcdock/pcdock-autod --farm 127.0.0.1:9001 --data %h/.local/share/pcdock-autod` и `After=pcdockd.service`.
`systemctl --user enable --now pcdockd`. Пользователь должен иметь право на USB-устройства (группа `plugdev` и правила udev) и
доступ к серверу ADB (`adb start-server` от того же пользователя). Службу для Windows и macOS в проекте не поставляем.

### Остановка

Ctrl+C или SIGTERM: демон пишет `завершаюсь…`, ферма останавливает потоки телефонов и возвращает телефоны в обычный режим (сброс USB, на
это уходит несколько секунд), затем процесс завершается с кодом 0. Закрытие терминала (SIGHUP) и `kill -9` так не обрабатываются: AOA-телефон останется в режиме аксессуара, и приложение при
следующем запуске само не стартует (поможет переподключение кабеля). В ADB-режиме сервер на телефоне завершится сам при
закрытии потока.

## 6. Настройка

Все параметры: [daemon.md](daemon.md#параметры) (демон) и [farm.md](farm.md#farmconfig) (библиотека, JSON). Что чаще настраивают:

| Параметр | Когда менять |
|---|---|
| `lost_after` (45 с) | WSL через usbipd: возврат после сброса до ~40 с (оставить 45+). Нативный Linux: можно уменьшить до 10–15 с, чтобы быстрее узнавать о пропаже |
| `fallback_after` (20 с) | как долго ждать рабочего пути, прежде чем пробовать другой |
| `every` (2 с) | период опроса; hotplug-события будят обнаружение раньше |
| `vendor_ids` | добавить производителя, которого нет в списке |
| `adb_local_port` (47000) | если порты 47000+ заняты |
| `audio` / `video` | значения по умолчанию для новых телефонов (меняются командой `SetStream`) |

## 7. Состояния и что делать

| Состояние в логе / событии | Причина | Действие |
|---|---|---|
| `needs_access` | нет прав на USB-устройство | Linux: правила udev (`pcdock-probe --udev-rules`), запущен ли `udevd` (`ps -e \| grep udevd`), переподключить. WSL: включить systemd, см. transports.md. Windows: WinUSB |
| `needs_auth` | ADB ждёт подтверждения | на телефоне «Разрешить отладку по USB с этого компьютера» |
| `needs_app` | в режиме аксессуара приложение молчит | установить приложение; посмотреть экран телефона (диалог «Открыть для аксессуара?» или «Начать запись?»); проверить автозапуск на HyperOS |
| `needs_permission` | нет разрешения записи экрана | на телефоне нажать «Начать» |
| `connecting` дольше минуты | телефон виден, но не отвечает | смотреть лог (`-v`); проверить кабель; для ADB: работает ли `adb devices` |
| `lost` | телефон пропал дольше `lost_after` | проверить кабель, проброс (WSL), `adb devices` |
| (телефона нет в списке вообще) | VID не в списке, нет проброса, нет прав у `adb`, для ADB нет `server_apk` | `lsusb`, `pcdock-probe --list`, `--vid`, `adb devices` |

## 8. Диагностика

**`pcdock-check`**: самопроверка на вашей машине (Linux, macOS, Windows). Находит телефоны, проверяет USB и ADB, готовность, размер экрана, поток кадров и,
с флагом `--input`, ввод (свайп вниз и вверх и Назад на телефоне). По умолчанию только читает. Печатает отчёт и возвращает код 0, если провалов нет:

```bash
pcdock-check --server-apk server-adb-debug.apk --input --json report.json
```

Первым делом запускайте её при любой неполадке и присылайте отчёт.

**Логи.** По умолчанию уровень `info`. `-v` включает `debug`, `-vv` `trace` (или переменная `RUST_LOG`). Демон пишет в stderr. Библиотека
(ферма) сама ничего не пишет: о событиях она сообщает событиями и предупреждениями (`Warning`).

**Утилита `pcdock-probe`:**

| Команда | Что делает |
|---|---|
| `pcdock-probe --list [--serials]` | список телефонов на USB (порт, VID:PID, режим, серийник) |
| `pcdock-probe --udev-rules` | печатает правила udev для списка производителей |
| `pcdock-probe --hotplug --seconds 30` | показывает события подключения и отключения |
| `pcdock-probe [--port 1-2.3 \| --serial СЕР] [--seconds N] [--tap] ...` | подключается к телефону по AOA и качает видео |

**Типичные неполадки**

| Симптом | Причина | Что делать |
|---|---|---|
| `adb devices` пуст, а `lsusb` телефон показывает | у процесса `adb` нет прав на USB-устройство | см. `needs_access` |
| телефон есть в `lsusb`, но ферма его не видит | VID не в списке | `--vid 0x....` |
| в ADB-режиме `connecting` и в логе «нужен APK сервера» | не задан `server_apk` | `--server-apk` или `PCDOCK_SERVER_APK` |
| ADB-телефон `ready`, но кадров нет | не вызван `Watch`: видео на телефоне идёт по спросу | подписаться на телефон |
| `Error: передача файлов выключена` | демон запущен без `--files` | `pcdockd --files` |
| `Error: путь … вне разрешённых папок` | файл вне `/sdcard`, `/storage/emulated/0`, `/data/local/tmp` | другой путь или `--files-root` |
| `Error: … не выделен` / `занят прогоном` (автоматизация) | телефон занят другим прогоном | дождаться или `Stop` |
| автоматизация: «нет связи с pcdockd» | `pcdockd` не запущен или другой адрес | `pcdock-autod --farm …`, она переподключится сама |
| клиент вдруг отключился | события копились без чтения (более 4096 штук или 2 МБ) | читать события быстрее; кадры при этом не накапливаются |
| в WSL телефон исчезает при переходе в AOA | не разрешён проброс USB-ID режима аксессуара | `usbipd bind --hardware-id 18d1:2d00` и `18d1:2d01` |
| в WSL телефон не возвращается после смены режима USB | новый USB-ID не разрешён | `usbipd bind` для нового ID |
| установка приложения «висит» | на телефоне ждёт подтверждение установки по USB | нажать на экране телефона |
| после перезапуска приложения нет картинки по AOA | нет разрешения записи экрана | нажать «Начать» на телефоне |
| при выходе телефон остался в режиме аксессуара | процесс убит жёстко | переподключить кабель |
| «слушать не на localhost можно только с паролем» | `--tcp`/`--ws` не на localhost без `--token` | указать `--token` или localhost |

## 9. Безопасность

- Управление телефоном и просмотр экрана доступны любому, кто подключился к слушателю. У `pcdock-autod` дополнительно можно запускать сценарии (они видят экран и управляют телефонами, но не имеют доступа к файлам и сети ПК: песочница Lua). По умолчанию слушатели только на `localhost`;
  вне localhost демон запускается только с `--token`. Токен передавайте через `PCDOCK_TOKEN`, а не аргументом: аргументы видны в списке процессов.
- Шифрования нет. Наружу выставляйте через VPN, SSH-туннель или обратный прокси с TLS.
- ADB-сервер на телефоне принимает соединения только от пользователя shell; сокет доступен всем приложениям телефона, но чужие
  соединения закрываются.
- Файлы (`--files`): пути только на телефоне, в разрешённых папках; путь на ПК от клиента не принимается, данные идут потоком через демон.
- `server-adb-debug.apk` лежит в `/data/local/tmp` телефона и запускается с правами shell. Выдавайте APK только из доверенной сборки.
- Ферма открывает USB-устройства только производителей из списка. Не добавляйте `--vid` для периферии и контроллеров.
- Не включайте `serial` в системах, где к портам подключены чужие устройства.

## 10. Известные ограничения

- Проверено на Linux (в WSL2) и двух телефонах Android 15. сборка и тесты на Windows и macOS проходят в CI; на настоящей Windows запускались бинарники (libusb, именованная труба), но с телефоном на Windows не проверялось, на настоящем macOS не запускалось (запустите `pcdock-check`).
- Передача файлов и сценарии автоматизации проверены тестами и запуском бинарников с фейковыми телефонами; на настоящем телефоне не прогонялись. Файлы по AOA недоступны (только по ADB).
- У `pcdock-autod` нет анализа изображений (CV отложено): сценарий получает кадры и факт изменения картинки, но не пиксели.
- Звук: канал работает, но слышимый звук (с источником) не проверялся.
- Мышь: команды принимаются, но результат (положение курсора) в кадрах не виден, так как указатель не рисуется.
- Выключенный экран и побудка: код есть, на телефоне не проверялись.
- Захват экрана ADB-сервера проверен на Android 15; для старых версий нужен запасной путь (не реализован).
- Закрытые системные интерфейсы Android (захват, ввод, звук) могут измениться в новых версиях.
- `--video` у демона нельзя выключить флагом (управляйте потоком командой клиента `SetStream`).
- В WSL2 переключение USB-режима телефона требует ручного разрешения нового ID в `usbipd`.
- Нет шифрования в демонах. Доступ один общий токен: ролевой доступ относится к уровню приложения над демонами и в продукт не входит (вопрос отложен).
- Состояние хранится в памяти: после перезапуска демона номера телефонов выдаются заново.
- Serial-транспорт проверен только на паре сокетов, не на микроконтроллере.

## 11. Обновление

Бинарники и APK обновляются вместе. Версия протокола между ПК и телефоном (v2) проверяется в рукопожатии; несовместимые версии
телефон и ПК отклоняют с ошибкой. Приложение AOA обновляется `adb install -r`; сервер ADB-режима обновляется автоматически
(ферма при каждом подключении заново кладёт актуальный APK).
