# Архитектура

## Слои

```
 клиенты: UI, CI, скрипты, браузер                     (любой язык: протокол демонов)
        │                         │
        ▼ протокол автоматизации  ▼ протокол фермы
 ┌──────────────────┐    ┌──────────────────────────────────────────────┐
 │  pcdock-autod     │───►│  pcdockd (pcdock-serve поверх pcdock-farm)    │
 │  Lua, прогоны,    │    │  телефоны, кадры, ввод, файлы                 │
 │  отчёты, CV позже │    └──────────────────────────────────────────────┘
 └──────────────────┘            │ PhoneLink: один телефон = один канал
        общая основа (pcdock-net: носители, ящик, пароль)
                      ┌────────────┬────────────┬──────────────┐
                      │ pcdock-usb │ pcdock-adb │ pcdock-serial │   транспорты
                      └────────────┴────────────┴──────────────┘
                                   │
                  pcdock-core  (Session, пакеты, HID, ввод): не знает ОС, без ввода-вывода (sans-IO)
```

`pcdock-autod` это клиент `pcdockd`: он говорит с ним тем же протоколом, что и любой другой клиент. Поэтому автоматизация и вычисления над кадрами
не мешают ферме: отдельный процесс, подписка на кадры с нужной ему частотой, медленный клиент отключается сервером, а не тормозит остальных.
Решения принимает ферма, демоны только переводят события в сообщения и команды в вызовы.

## Крейты

| Крейт | Назначение |
|---|---|
| `pcdock-core` | Протокол ПК-телефон v2: пакеты, `Session`, HID-отчёты, модель ввода, интерфейсы транспорта (`PhoneLink`, `Discovery`, `LinkFactory`, `PhoneState`). Без ввода-вывода и без `unsafe`. |
| `pcdock-usb` | AOA по USB через libusb: перебор телефонов, handshake, выбор по порту или серийнику, `UsbLink`, `UsbDiscovery` (с событиями hotplug), утилита `pcdock-probe`. |
| `pcdock-adb` | ADB: клиент сервера ADB, загрузка и запуск серверного процесса на телефоне, файлы, `AdbLink`, `AdbDiscovery`. |
| `pcdock-serial` | Последовательная труба (микроконтроллер): `SerialLink`, `SerialDiscovery`. |
| `pcdock-farm` | `Farm`: живая ферма с потоками, `FarmConfig`. Внутренний крейт. |
| `pcdock-net` | Общая основа демонов: носители (TCP, WebSocket, локальная труба), исходящий ящик клиента, приветствие, пароль, `id` запросов. |
| `pcdock-serve` | Протокол фермы поверх `pcdock-net`: подписки с условиями, видео по спросу, файлы. |
| `pcdock-client` | Клиент протокола демонов для Rust (TCP и локальная труба). |
| `pcdockd` | Демон фермы. |
| `pcdock-autod` | Демон автоматизации: движок Lua, хранение сценариев, прогоны, события, отчёты. |
| `pcdock-check` | Самопроверка на машине пользователя. |

## Потоки

- **Поток на телефон.** `Farm` запускает отдельный поток на каждый телефон: он подключает канал, читает его, отдаёт ввод, переподключается.
- **Обнаружение** выполняется в вызове `Farm::drain()` (по таймеру, по умолчанию раз в 2 с, и сразу после события hotplug); USB-источник держит свой поток событий libusb.
- **`pcdockd`** держит поток раздачи: каждые 5 мс забирает события фермы и рассылает клиентам; на клиента один-два потока чтения и записи.
- **`pcdock-autod`**: поток на каждый прогон (свой Lua), поток связи с `pcdockd` (с переподключением), потоки событий и кадров.

## Путь данных

Видео: телефон, кадр JPEG, пакет v2, канал (USB bulk, TCP через adb, serial), `Session`, событие `Video`, ферма (кэш последнего кадра), подписчики (отбор по условиям каждого).

Ввод: клиент, команда протокола, `InputCmd`, поток телефона, `Session` (HID-отчёт), канал, телефон. По AOA отчёт идёт как HID-событие USB, по ADB и serial как
управляющий пакет, который сервер на телефоне превращает в событие ввода.

Файлы: клиент, пакеты типа 3 через демон, `adb exec` на телефоне. На диск ПК ничего не пишется.

## Гарантии доставки

- **Видео:** важен последний кадр; у каждого клиента один слот «последний кадр»; пропуск виден по `seq`. Разрешение всегда оригинальное.
- **Видео по спросу:** нет подписчиков, видео на телефоне выключено; есть, телефон снимает с частотой самого требовательного.
- **События состояния и управления** не теряются; клиент, который их не читает, отключается.
- **Звук:** очередь ограничена, лишнее отбрасывается.
- **Файлы:** надёжно и по порядку, с ожиданием; `FileDone` строго после последнего пакета данных.
- **Ввод** уходит в порядке отправки; пока связи нет, он копится в сессии.

## Идентичность телефона

Телефон узнаётся по **серийнику** (`ro.serialno`): он одинаков в обычном режиме, в режиме аксессуара и в ADB. Поэтому телефон, видимый по USB и по ADB,
ферма считает одним. Номер (`PhoneId`) ферма выдаёт сама и сохраняет за серийником, пока работает. Адрес USB-порта (`1-2.3`) не идентичность: после
переподключения он может смениться (в WSL бывает всегда).
