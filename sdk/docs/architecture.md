# Архитектура

## Слои

```
 потребитель: приложение на Rust / C / Python / браузер / другой процесс
        │                         │
        │ (библиотека)            │ (сокеты: TCP, WebSocket, локальная труба)
        │                         ▼
        │                 pcdockd  (демон)  ──  pcdock-serve (протокол приложения)
        ▼                         │
   ┌───────────────────────────────────────────────┐
   │  pcdock-farm  (Farm): все телефоны             │  владеет жизненным циклом:
   │  обнаружение, подключение, переподключение,     │  находит, подключает, склеивает пути,
   │  состояния, кэш кадров, ввод                    │  сообщает о состоянии
   └───────────────────────────────────────────────┘
        │ PhoneLink (один телефон = один канал)
   ┌────────────┬────────────┬─────────────┐
   │ pcdock-usb │ pcdock-adb │ pcdock-serial│  транспорты: байты и управляющие запросы
   └────────────┴────────────┴─────────────┘
        │
   pcdock-core  (Session, пакеты, HID, ввод)   ← не знает ОС, не делает ввод-вывод (sans-IO)
```

Принцип: каждый слой знает только о нижнем. Демон ничего не решает про телефоны, он только переводит события фермы
в сообщения для клиентов и команды клиентов в вызовы фермы. Любой потребитель получает то же поведение, что и демон,
потому что демон использует ту же ферму.

## Крейты

| Крейт | Назначение |
|---|---|
| `pcdock-core` | Протокол v2: пакеты, `Session`, HID-отчёты (тачскрин, мышь, клавиатура), модель ввода, интерфейсы транспорта (`PhoneLink`, `Discovery`, `LinkFactory`, `PhoneState`). Без ввода-вывода и без `unsafe`. |
| `pcdock-usb` | AOA по USB через libusb: перебор телефонов, handshake, выбор по порту или серийнику, `UsbLink`, `UsbDiscovery` (с событиями hotplug), утилита `pcdock-probe`. |
| `pcdock-adb` | ADB: клиент протокола сервера ADB, загрузка и запуск серверного процесса на телефоне, `AdbLink`, `AdbDiscovery`. |
| `pcdock-serial` | Последовательная труба (микроконтроллер): `SerialLink`, `SerialDiscovery`. |
| `pcdock-farm` | `Farm` (живая ферма с потоками), `FarmConfig`, `Registry` (sans-IO реестр сессий для тех, кто возит байты сам). |
| `pcdock-ffi` | C ABI: `pcdock_farm_*` (живая ферма), `pcdock_registry_*` (реестр), `pcdock_session_*` (одна сессия). |
| `pcdock-serve` | Протокол приложения и носители TCP, WebSocket, локальная труба. |
| `pcdockd` | Исполняемый файл демона: аргументы → `FarmConfig` → ферма → слушатели. |

## Потоки

- **Поток на телефон.** `Farm` запускает отдельный поток для каждого телефона: он подключает канал, читает его, отдаёт ввод,
  переподключается при обрыве. Снаружи потоков не видно.
- **Обнаружение** выполняется в вызове `Farm::drain()` (по таймеру, по умолчанию раз в 2 секунды, и сразу после события
  hotplug). Отдельного потока для него нет, но USB-источник держит свой поток обработки событий libusb.
- **Демон** держит поток раздачи: он каждые 5 мс вызывает `drain()` и рассылает события клиентам; на каждого клиента один
  или два потока чтения/записи.
- `Farm` не потокобезопасна сама: вызывайте её из одного потока или держите под мьютексом (демон так и делает).

## Путь данных

Видео: телефон → кадр JPEG → пакет v2 → канал (USB bulk / TCP через adb / serial) → `Session` → событие `Video` →
`Farm` (кэш последнего кадра, номер кадра) → клиент.

Ввод: клиент → `InputCmd` → `Farm::command` → поток телефона → `Session` (HID-отчёт) → канал → телефон. По AOA отчёт
идёт как HID-событие USB, по ADB и serial как управляющий пакет с шапкой `0xC0`, который сервер на телефоне превращает в
событие ввода.

## Гарантии доставки

- **Видео:** важен последний кадр. Если клиент не успевает, старые кадры отбрасываются; каждый кадр имеет возрастающий
  номер `seq`, по пропускам клиент видит потерю. Последний кадр хранится в ферме всегда (`last_frame`), даже без подписки.
- **Видео идёт клиенту только от телефонов, за которыми «следят»** (`set_watching` / `Watch`). Это экономит трафик на
  сетке плиток.
- **Звук:** очередь ограничена; при переполнении отбрасывается.
- **События состояния и управления** (`Appeared`, `State`, `Lost`, `Connected`, `Display`…) не теряются.
- **Ввод** уходит в порядке отправки; пока связи нет, он копится в сессии.

## Идентичность телефона

Телефон узнаётся по **серийнику** (`ro.serialno`): он одинаков в обычном режиме, в режиме аксессуара и в ADB. Поэтому
один телефон, видимый по USB и по ADB, ферма считает одним. Номер телефона (`PhoneId`, число от 1) ферма выдаёт сама и
сохраняет за серийником, пока работает: вернувшийся телефон получает прежний номер. Адрес USB-порта (`1-2.3`) не
идентичность: после переподключения он может смениться (особенно в WSL).
